 <코드 5> 면적과 기후만 넣으면 나머지가 전부 유도된다
 --------------------------------------------------------------------------
 function generateIsland(seed, tier, climate): IslandState {
   const T = ISLAND_TIERS[tier];
   const C = CLIMATE_PROFILES[climate];
   const rng = makeRng(seed);

   // 1) 격자
   const cellCount = (T.areaKm2 * 1e6) / (T.cellM ** 2);
   assert(cellCount <= ECO_CONST.maxCells);            // [I-2.2]

   // 2) 지형 - 최고 고도만 티어가 강제하고 형태는 시드가 만든다
   const cells = generateTerrain(rng, cellCount, T.maxElevM, T.geology);

   // 3) 기후 - 24_3층_순환 / 25_기온엔진을 1년치 미리 돌려 평형을 잡는다
   //    바이옴 태그는 여기서 '계산되어' 붙는다. 칠하지 않는다. [I-3.1]
   spinUpClimate(cells, C, 365);
   tagBiomes(cells);
   assert(distinctBiomes(cells) >= T.biomeCount);

   // 4) 은신처 검증 - 미달이면 리롤 [W-4.5][I-3.3]
   const effKm2 = T.areaKm2 * T.habitableFrac;
   const needRefugia = Math.ceil(effKm2 / ECO_CONST.refugiaPerKm2);
   if (countRefugia(cells) < needRefugia) return generateIsland(seed+1, tier, climate);

   // 5) 종 목록 - 종-면적 곡선 [I-6.4]
   const nSpecies = Math.round(
       ECO_CONST.richnessBase
     * Math.pow(T.areaKm2 / 1000, ECO_CONST.richnessExponent)
     * C.richnessFactor);
   const species = rollSpecies(rng, nSpecies, climate);   // C-5.3 비율 배분
   enforceDietWidth(species);                             // C-5.2 대체재 강제

   // 6) 부양 개체수 [I-4]
   const pops = deriveCarryingCapacity(C, effKm2, tier);

   // 7) MVP 판정 [I-6.1] - 여기서 티어의 성격이 갈린다
   for (const s of species) {
     const n = pops[s.trophic] * shareOf(s, species);
     s.status = n < ECO_CONST.mvpShortTerm ? "ABSENT"
              : n < ECO_CONST.mvpLongTerm  ? "SEMI_VIABLE"
              :                              "VIABLE";
   }

   // 8) 자원 캡 [I-7]
   const iron = T.geology === "CORAL_OR_REMNANT"
              ? 0 : ECO_CONST.oreIronTonPerKm2 * T.areaKm2;

   return assemble(...);
 }

 function deriveCarryingCapacity(C, effKm2, tier) {          // [I-4] 그대로
   const F = C.nppTonPerKm2Yr * C.browseAvailability * ECO_CONST.sustainableOfftake;
   const yr = (kg) => kg * ECO_CONST.dailyIntakeFrac * 365 / 1000;

   const massT3 = C.bodyMassT3Kg * (tier === "S" ? ECO_CONST.dwarfismFactorS : 1);
   const dT2 = (F * C.splitT2) / yr(ECO_CONST.bodyMassT2Kg);
   const dT3 = (F * C.splitT3) / yr(massT3);

   const preyKg = dT2 * ECO_CONST.bodyMassT2Kg + dT3 * massT3;
   const predKg = preyKg * ECO_CONST.predatorBiomassFrac;
   const dT4 = (predKg * ECO_CONST.splitT4) / ECO_CONST.bodyMassT4Kg;
   const dT5 = (predKg * ECO_CONST.splitT5) / ECO_CONST.bodyMassT5Kg;

   return { T2: dT2*effKm2, T3: dT3*effKm2, T4: dT4*effKm2, T5: dT5*effKm2 };
 }

 [S-3.1] 7단계 MVP 판정이 이 설계의 심장이다.
         "10 km2 섬에 늑대를 넣지 않는다"는 결정이 코드 어디에도 없고,
         면적 x 상수 계산 결과 40마리가 안 되어 ABSENT가 될 뿐이다.
         면적을 늘리면 늑대가 저절로 나타난다. (원칙 P6)

[S-4] 일 단위 틱 파이프라인
--------------------------------------------------------------------------------

 환경은 게임 틱마다가 아니라 하루 1회 갱신한다.
 셀 수가 6,250 이하이므로 전체 비용은 수 ms 수준이다. (25_기온엔진 [T-6])

 <코드 6> 하루 파이프라인 - 순서가 곧 인과다
 --------------------------------------------------------------------------
 function ecologyDay(isl: IslandState) {
   const C = CLIMATE_PROFILES[isl.climate];
   const season = seasonFactor(isl.dayOfYear, C);   // 연교차로 유도

   // --- 1. 물리층 (24_/25_ 문서 소유) ---
   for (const c of isl.cells) {
     c.tempC = solarHeat(c, season)                 // T-1
             - c.elevationM * LAPSE_PER_M           // T-3
             + advection(c) + thermalMass(c);       // T-4, T-2
   }
   computeWind(isl.cells);                          // W-3.2
   computeRainfall(isl.cells);                      // W-3.4 지형성 강수

   // --- 2. 물 수지 ---
   for (const c of isl.cells) {
     c.soilWaterMm += c.rainfallMm
                    - evapotranspiration(c)
                    - runoff(c, C.runoffCoef);
     c.soilWaterMm = clamp(c.soilWaterMm, 0, fieldCapacity(c));
     c.isPermanentWater = c.soilWaterMm > PERMANENT_THRESHOLD || isSpring(c);
   }
   updateWaterAccess(isl.cells);        // 사바나 건기 집결의 입력 [C-4.2]

   // --- 3. 식생 성장 (로지스틱 + 3중 제한) ---
   const halted = isGrowthHalted(isl.dayOfYear, C);   // 온대 겨울 / 사바나 건기
   for (const c of isl.cells) {
     if (halted) continue;                            // r = 0. 뺄셈만 남는다
     const fW = clamp(c.soilWaterMm / waterDemand(C), 0, 1);
     const fT = gaussian(c.tempC, C.tempOptC, TEMP_SIGMA);
     const r  = (C.regrowthRatePerYr / 365) * fW * fT * c.fertility;
     c.standingBiomassT += r * c.standingBiomassT
                             * (1 - c.standingBiomassT / c.biomassCapT);
   }

   // --- 4. 화재 (fireEnabled 기후만) [C-4.5] ---
   if (C.fireEnabled) resolveFires(isl, C);

   // --- 5. 초식 섭식 ---
   for (const c of isl.cells) {
     const edible = c.standingBiomassT * C.browseAvailability;
     const demand = herbivoreDemand(c);              // 체중 x 0.03 x 마릿수
     const taken  = Math.min(edible, demand);
     c.standingBiomassT -= taken;
     distributeEnergy(c, taken);                     // 부족분은 에너지 감소
     if (taken < demand) degradeVegetation(c);       // 과채식 -> 지력 하락
   }

   // --- 6. 포식 (등급으로만 판정. 종 이름 금지 R-12.3) ---
   for (const c of isl.cells) {
     for (const pred of predatorsIn(c)) {
       const target = pickByRatio(c, pred);          // 에너지획득 / 사냥위험 R-5.3
       resolveHunt(c, pred, target);
     }
     c.fearField = decay(c.fearField) + huntPressure(c);
   }

   // --- 7. 이동 : 대이동은 여기서 '저절로' 일어난다 [C-4.3] ---
   for (const g of mobileGroups(isl)) {
     const uThirst = thirstUtility(g) / distToWater(g);
     const uFeed   = feedUtility(g)   * localBiomass(g);
     const uFear   = -g.cell.fearField * g.timidity;
     moveToward(g, argmaxNeighbor(uThirst + uFeed + uFear));
   }

   // --- 8. 번식과 사망 ---
   for (const c of isl.cells) {
     applyBirths(c);                 // 에너지 > 임계 + 성체 + 이성 근접
     applyDeaths(c);                 // 에너지 0 -> 사망 (R-12.2)
     applyInbreedingPenalty(c);      // SEMI_VIABLE 종만
   }

   // --- 9. 지력 ---
   for (const c of isl.cells) {
     c.fertility += recoverRate(c) * C.fertilityRecoverMul
                  - drainRate(c)   * C.fertilityDrainMul;
     c.topsoilCm -= erosion(c);      // 강수 x 경사 x (1 - 식생피복)
   }

   isl.dayOfYear = (isl.dayOfYear + 1) % 365;
 }
 --------------------------------------------------------------------------

 [S-4.1] 순서를 바꾸면 인과가 바뀐다. 특히 3(성장) -> 5(섭식) -> 6(포식)
         -> 7(이동) -> 8(번식/사망)의 순서는 고정이다.
         섭식보다 번식을 먼저 처리하면 굶어 죽을 개체가 새끼를 낳는다.

 [S-4.2] 3번의 halted 분기가 온대와 사바나를 가른다. 같은 코드이고
         isGrowthHalted가 참조하는 상수(growthHaltMonths)만 다르다.
         온대는 겨울에, 사바나는 건기에 참이 된다.
         이 한 줄에서 '겨울 아사'와 '건기 대이동'이 동시에 나온다.

 [S-4.3] 7번의 세 효용 합이 [C-4.4]가 말한 "대이동은 시스템이 아니라
         효용의 교차점"의 구현이다. Migration 클래스를 만들지 않는다.

 [S-5.1] 16_성능_LOD <표 7>의 등급을 섬 생태계에 대응시킨다.
   L0 : 유저 반경 내 셀. 개별 Entity로 인스턴스화. 매 게임 틱.
   L1 : 인접 셀. 개별 상태 유지, 행동은 4틱마다.
   L2 : 원거리 셀. pop 밀도 필드만. 하루 1회 [S-4] 전체 수행.
   L3 : 관측 이력이 없는 셀. 개체군 방정식으로 7일치를 한 번에 적분.

 [S-5.2] 인스턴스 예산([I-9.3])을 초과하면 [I-9.4] 우선순위의 역순으로
         개체를 pop 필드로 되돌린다(demote). T6 인간은 절대 demote하지 않는다.

 [S-5.3] L3 -> L0 승격 시 pop 밀도를 개체로 역산 복원한다. 이때
         연령 · 에너지 분포는 저장된 통계 모멘트에서 샘플링한다.
         (R-15.3 "모순 없이 역산 복원")

 [V-1] T-11  무인 생태계 장기 안정성
   인간 0명으로 500년 진행. 가뭄 · 폭풍 · 전염병을 무작위 주입.
   합격 : L · XL 티어에서 T0~T3 등급이 하나도 영구 소멸하지 않는다.
          M 티어는 준자립 종 1개까지 소멸 허용.

[S-8] 1차 구현 결과 (XL × 사바나, 헤드리스 70년 검증)
--------------------------------------------------------------------------------

 32_사바나XL_생태시뮬.html이 [S-1]~[S-4]를 구현한 첫 사례다.
 아래는 그 실행 결과이며, 문서가 틀린 곳을 실행이 짚어낸 기록이다.

 [S-8.1] 통과한 것
   · [V-1] T-11 : 70년간 T0~T5 영구 소멸 없음. 개체수가 완충 구역 안에서
                  진동한다(T3 4,800~9,700). [W-4.2] 충족.
   · [V-2] T-12 : 육지 6,250셀 정확히 일치. 25년 시뮬 4.4초(하루당 0.5ms).
   · [V-5] 화재 : 연 20~45% 소실, 낙뢰 발화 4~10건. 화재가 목본을 26~29%로
                  붙잡는 것이 확인된다. [C-4.5] 충족.
   · [C-6] 표 C-2 : 개입 3종이 전부 예측대로 작동한다.
                    화재 진압 20년 -> 목본 26%->57%, T3 -15%(대조군 +26%)
                    대형 육식 전멸 -> T3 +131%
                    강수 -40%      -> T3 -73%

 [S-8.2] 문서가 틀린 곳 - 세 가지

  (가) <표 I-3>의 초식 개체수는 평형이 아니라 관리 목표값이다.
       u = 0.10에서 초식 수요는 초본 현존량의 6% 남짓이라, 초식은 섬 전체
       규모에서 식량 제약을 받지 않는다. 실제 평형은 T3 약 7,500으로
       유도값 24,041의 30% 수준이며, 이를 붙잡는 것은 먹이가 아니라
       포식압과 건기 수원 접근성이다.
       결정적 증거 : 포식자를 전멸시키면 T3가 17,493까지 올라 24,041에
       근접한다. 즉 [I-4]가 유도한 것은 '포식이 없을 때의 상한'이었다.
       -> [I-4] 유도식에 포식 압력과 수원 제약 항을 추가해야 한다.
          현재의 7단계는 먹이 하나만 보고 있다.

  (나) [V-5]의 '건기 수원 반경 국소 밀도 10배'는 관측되지 않는다.
       국소 밀도 배율은 상시 3~5.7배이고, 건기에는 오히려 분산한다
       (수원 1셀 이내 개체 비율 우기 65% -> 건기 47%).
       수원 주변 초지가 먼저 고갈되어, 무리가 멀리 나가 뜯고 돌아와 마시는
       '통근'이 되기 때문이다.
       -> 집결이 아니라 통근이 사바나의 실제 거동이다. [C-4.2]의 서술과
          [V-5]의 판정 기준(3배)을 이에 맞춰 고칠 것.

  (다) 항구 수원 비율이 은신처와 동급의 생성 검증 항목이다.
       항구 수원이 육지의 1.0%면 무리 대부분이 물에 닿지 못해 첫 건기에
       전멸한다. 2.5%에서 계통이 유지된다.
       -> [I-3.3] 은신처 리롤 조건에 '항구 수원 >= 유효면적의 2%'를
          같은 등급으로 추가할 것.

 [S-8.3] 구현하며 드러난 함정 - 다음 기후대에서도 반복될 것들
   · 초본과 목본을 한 풀로 두면 현존량 40 t/ha와 NPP 800 t/km2/년을
     동시에 표현할 수 없다(회전율이 맞지 않는다). 반드시 분리한다.
     분리해야 [C-4.6] 화재-목본-초지 연쇄도 계산으로 나온다.
   · 무리에 분열만 있고 병합이 없으면 무리 수가 단조 감소하면서 개체가
     계속 샌다. 원칙 P8 위반이다. 병합은 선택이 아니라 필수다.
   · 이동 보폭이 셀 하나보다 작으면 동물이 수원까지 통근하지 못해
     갈증사한다. 400m 격자에서 유제류는 하루 0.3~3.6셀을 움직여야 한다.
   · 포식자가 무한한 대체먹이(T2)로 배를 채우면, 줄어드는 주 먹이(T3)를
     끝까지 사냥해 멸종시킨다(초포식). 대형 육식의 대체먹이 의존도에
     상한(소요의 40%)을 두어야 수적 연동이 생긴다.

  (라) [C-4.6]의 '불을 끄면 사냥감이 사라진다'에 시간 척도가 빠져 있다.
       화재는 초본의 최대 소비자다(연 28~33% 소실). 따라서 불을 끄면
       단기에는 먹이가 늘어 초식이 오히려 증가한다.
         진압 10년  T3 +31%  · 목본 임관 48%
         진압 20년  T3  +8%  · 목본 61%
         진압 100년 T3  -4%  · 목본 76% · 초본 절반 (여기서 역전)
       -> 방향은 맞지만 100년 규모의 이야기다. 단기 효과는 정반대이므로
          [C-4.6] 서술에 시간 척도를 명시할 것.
          "불을 끄면 먼저 살찌고, 100년 뒤 굶는다"가 정확한 요약이다.
