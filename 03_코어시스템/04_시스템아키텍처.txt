 <그림 1> 전체 구조도

     [브라우저 클라이언트]  React (+ 최소한의 Canvas)
              |
              |  WebSocket : 변경분(Delta)만 수신
              |  REST      : 로그인, 정적 데이터, 크로니클 조회
              v
   +===============================================================+
   |               게임 서버 (Node.js / TypeScript)                |
   |                                                               |
   |  +------------+   매 틱 아래 순서로 실행                      |
   |  | Tick Loop  |-- 1) 시간 경과 / 욕구/에너지 감쇠             |
   |  +------------+-- 2) 생태계 시뮬 (식물 성장, 포식, 번식)      |
   |                 -- 3) 지각(Perception) : 이벤트 목격          |
   |                 -- 4) 기억 기록 및 관계 추론                  |
   |                 -- 5) 대화 -> 기억 전파(Gossip)               |
   |                 -- 6) 행동 결정 (Utility AI)                  |
   |                 -- 7) 행동 실행 / 이동                        |
   |                 -- 8) 경제 정산 (생산/소비/가격/캐러밴)       |
   |                 -- 9) 크로니클 기록 + 델타 브로드캐스트       |
   +===============================================================+
              |                              |
              v                              v
     [Redis : 실시간 상태]          [PostgreSQL : 영속 데이터]
      엔티티 상태 캐시, 큐           엔티티/기억/거래원장/크로니클

  * 틱 규격 : 1 tick = 게임 내 10분 = 실시간 3초
              (하루 = 144 tick = 실시간 약 7.2분)
  * 클라이언트는 연산하지 않는다. 서버 상태를 그리기만 한다.
  * 네트워크 : 전체 스냅샷 전송 금지. 변경된 필드만 델타 전송.
               인구 100명 기준 틱당 평균 페이로드 목표 < 4KB
